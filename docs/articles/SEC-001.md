# SEC-001: Hardcoded credential

**Blocks completion** (priority 1).

## What it means

A password, token, API key or other secret is written in a script as a string. For example:

- a value assigned to `password`, `apiKey`, `clientSecret` or `accessToken`;
- a literal password passed to `setBasicAuth()` or `setPassword()`;
- an `Authorization` header;
- a value that looks like an AWS key, GitHub or Slack token, JWT or private key.

The finding shows **where** the value is and how long it is, but never the value itself.

## Why it matters

Scripts are copied into update sets, version history, XML exports, clones and source control. Anyone who can read the script can read the secret, and deleting it later doesn't remove those copies.

## How to fix it

1. **Rotate the credential.** Assume it has leaked.
2. Remove it from the script.
3. Store it properly:
   - a **Credential** record used through a **Connection & Credential alias**; or
   - a REST Message **authentication profile**; or
   - an encrypted (password2) system property.

```javascript
// Before
request.setBasicAuth('svc.integration', 'S3cret!');

// After: the REST Message uses a Basic Auth profile
request.setAuthenticationProfile('basic', profileSysId);
```

## Not reported

- Values read at run time, such as `gs.getProperty(...)`.
- Placeholders like `changeme` or `<secret>`, field names like `u_password`, and message text.
